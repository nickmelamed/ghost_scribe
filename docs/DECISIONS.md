# Decisions

Design choices visible in the code, with the file each one comes from.

## D1. Use the community DAIGT v2 dataset, not the official competition file
The official training set has no per-model generation-source labels, and
the project needs them to hold out a source. (`data/preprocess.py`,
`data/processed/dataset_summary.md`)

## D2. Treat generation source as a stand-in for time
There is no timestamp axis, so each generating model is a "batch". Two
sources are held out to mimic a new model appearing. This is a
substitution and must not be described as real drift. (`docs/SPEC.md`,
`data/preprocess.py`)

## D3. Hold out falcon_180b_v1 and llama_70b_v1
Two sizeable, distinct model families, 1,055 and 1,172 rows.
(`HELD_OUT_SOURCES`)

## D4. Stratified 70/15/15 split by generation source, seed 42
So even the small sources appear in train, val, and test.
(`split_seen_pool`)

## D5. Classical features only in Stage 1, with a bigram-burstiness proxy
No LM perplexity, to keep Stage 1 cheap and fast. The proxy is documented
as an approximation. (`stage1/features.py`)

## D6. XGBoost is the Stage-1 decision model
Higher validation AUC than logistic regression (0.9930 vs 0.9837).
(`stage1/escalation_policy.py`, results)

## D7. Escalation bands set by percentile of distance from 0.5
Directly targets a 20% escalation rate instead of hoping fixed cutoffs
land in range. Calibrated on val. (`calibrate_bands`)

## D8. Two FPR variants for fairness
The 0.5-threshold FPR is comparable to the literature. The auto-flag-only
rate counts only people who would be flagged with no human in the loop,
which is the decision-relevant number for this tool. (`fairness/esl_eval.py`)

## D9. ELLIPSE as the ESL eval set
Real English Language Learner essays, not a proxy, but limited to US
grade 8-12 ELL students. The scope limit goes in the README.
(`fairness/data_prep_esl.py`)

## D10. Qwen2.5-3B-Instruct with LoRA, bf16 on MPS, no 4-bit
bitsandbytes does not support MPS and 64 GB memory fits a 3B model.
`requirements.txt` installs bitsandbytes on Linux only.
(`stage2/finetune_lora.py`)

## D11. Stage 2 fine-tunes on escalated cases only
The spec forbids fine-tuning on the full dataset. Only ambiguous cases
need the larger model. Rationales in the training target are
templated from real Stage-1 feature statistics, not generated by a model.
(`stage2/prepare_finetune_data.py`)

## D12. Asymmetric review queue
"AI-generated" verdicts always go to a human. Confident "Human-written"
verdicts may skip review, since clearing takes no action against a
student. This keeps a human on every accusatory path.
(`stage2/build_review_queue.py`, `stage2/confidence.py`)

## D13. Human-gate rate calibrated on val, with a 5-point margin
The gate rate is the smallest fraction of "Human-written" verdicts, least
confident first, that includes every val error where Stage 2 said human and
the essay was AI, plus 5 points. Ground truth is available only because the
data is simulated, and it is used only to set the rate. The test split gets
a read-only check and is never tuned on.

This replaces an earlier 20% rate that was set from test-split errors, which
conflicted with keeping test untouched. On val the old rate missed 1 of 9
errors, and the val-calibrated rate is 41.6% (see SPEC 6.1 for the numbers).
The margin is a fixed amount, not tuned, since there are only a handful of
errors. (`stage2/build_review_queue.py`, `results/review_gate.json`)

## D14. Review queue comes from the val split
Keeps the test split clean for evaluation. (`hitl/review_app.py`)

## D15. Reviewers never see ground truth
Labels are dropped before display, so reviews are blind like a real
deployment. (`hitl/review_app.py`, `hitl/llm_review.py`)

## D16. LLM reviewer uses the base model, kept in a separate file
Using the fine-tuned model would be close to grading its own work. LLM
reviews are never merged with human reviews, so a round trained on each
can be compared. (`hitl/llm_review.py`, `hitl/apply_corrections.py`)

Prompt history for the base-model reviewer, with measured accuracy:

- v1 had no rubric and used an academic-integrity triage framing. Accuracy
  was 61.7%, but it was degenerate, answering "Human-written" on 96.6% of
  cases.
- v2 (the version in use) has neutral framing, an explicit stylometric
  rubric, a debiasing instruction, and reasoning before the answer. Accuracy
  was about 64% with 9% unparsed, and the predictions were balanced. It was
  the best-calibrated version tested.
- v3 added two worked few-shot examples. It looked better at 75.8%, but that
  came from a truncation bug (52% unparsed) that silently fell back to
  Stage 2's own roughly 99%-accurate label. Once fixed and isolated from
  fallback rows, accuracy was 56.5%, barely above chance, and biased toward
  over-predicting "AI-generated". Few-shot examples made the model worse.
  Reverted.

An off-the-shelf 3B instruct model tops out well below Stage 2's 99.2%
on this task, however it is prompted. Keep it as a comparison baseline and
do not feed its output into round-2 retraining.

## D17. Corrections use the reviewer's label
Not Stage 2's suggestion and not ground truth. (`hitl/apply_corrections.py`)

## D18. Unparseable Stage-2 output falls back to Stage 1 and is counted
Fallbacks are logged in the results table, not silently dropped.
(`results/metrics_comparison.md`)

## D19. Raw data, processed splits, adapters, and reviews stay out of git
These are gitignored, and `data/download.py` documents how to fetch
the data. The results cannot be reproduced from the repo alone.

## D20. Remove near-duplicates from val, test and ESL at 80% shingle overlap
An essay is a near-duplicate when at least 80% of its 8-word shingles occur
in one train essay. The cutoff sits in a sparse part of the overlap
distribution, between 0.4 and 0.8 there are few rows and above 0.8 there are
many. Train is the reference and is left alone, test is also checked against
the kept val, and the held-out sources had no overlap. Removal is applied to
the derived files by text, which is valid only while the models, thresholds
and adapter are unchanged. Light edits can stay under the cutoff, so the
report counts the borderline rows kept. (`data/dedup.py`,
`results/dedup_report.json`)

## D21. Freeze the escalation thresholds after near-duplicate removal
The thresholds were calibrated on the old val. Keeping them means the only
thing that changed is the evaluation data, so the effect of the duplicates
can be read directly, and it avoids retraining Stage 2 for a small shift.
The escalation rate on the cleaned val is reported as measured. The
thresholds get recalibrated and Stage 2 retrained in round 2, which retrains
both stages anyway. (`stage1/models/escalation_thresholds.json`)

## D22. Prompt-held-out check uses a seeded draw of 3 prompts and a full retrain
Holding out prompts only means something if both stages are retrained
without them, so Stage 1 was refit, the bands were recalibrated on the seen
prompts' val rows, and Stage 2 was fine-tuned again on their escalated train
rows with unchanged hyperparameters. The three prompts come from
`random.Random(42)`, so they were not picked by hand. The same retrained
models are scored on held-out and seen prompts, which separates prompt shift
from the effect of retraining. It is a single draw, so the result carries
that variance, and k-fold over prompts was not run because each Stage-2 fit
takes about 4.5 hours on this machine. (`evaluation/prompt_holdout.py`)

## D23. Drift is measured against the pooled round-1 training data, with a noise level
AI sources are compared with the AI essays in train and the human control
with the human essays in train. Seen sources use their test rows and
unseen sources use all their rows. Because one source differs from a pooled
mixture even when the models trained on it, seen sources are also compared
with their own train rows, and each batch gets the 95th percentile of the
score PSI that a same-size bootstrap sample reaches. The 0.1 and 0.2
thresholds are the conventional ones and are reported as such, but they flag
most sources, so the report adds routing shares (cleared, escalated,
flagged) as the decision-relevant signal. (`drift/monitor.py`)

## D24. Round 2 introduces llama_70b_v1 and keeps falcon_180b_v1 unseen
Round 1 showed llama_70b_v1 shifting Stage 1's behavior (score PSI 0.509)
and falcon_180b_v1 mostly not (0.037). Introducing the one that drifted gives
round 2 something to absorb, and the quieter one stays unseen as a test of
generalization. It is also the larger source, with 1,172 essays.

## D25. Reviewed essays train with the reviewer's label and leave calibration
The reviewer's decision, not Stage 2's suggestion and not the ground truth,
is the training label, which is the point of the loop. Reviewed essays come
from val, so they are removed from the val rows that calibrate the bands and
the review gate. Evaluation still uses the true labels. The ESL and test rows
are checked against the new training data for near-duplicates, because
otherwise ELLIPSE essays that match a reviewed val essay would put the
fairness set back into training.

## D26. Round 2 retrains both stages from scratch and keeps the round-1 test group
Continuing from the round-1 adapter would be cheaper but would blur what
changed. A full retrain with the main run's hyperparameters changes only the
data. The round-1 test essays stay the comparison group, minus any removed as
near-duplicates, which `meta.json` counts. Costs per decision use the
documented illustrative units of 1, 5 and 25 and are not real money.
